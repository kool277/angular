# Fixes in this fork

This branch is Angular [v22.2.6](https://github.com/angular/angular/releases/tag/v22.2.6) plus the
fixes below. Each fix is one commit with only framework code and its test, so it can be sent to
Angular as it is. Each one has a demo in [`fork-tools/fix-demos/`](fork-tools/fix-demos/README.md)
that fails on stock 22.2.6 and passes on this fork.

The upstream issues were open, had no open pull request and were not labelled `state: confirmed`
on 2026-11-12 (Angular had not triaged them yet). Each fix starts with a test that failed on
v22.2.6.

| 1   | In component styles, a rule like `:host { &.active { ... } }` stopped working in 22.2.0: the style never applied to the component's element. | [#71050](https://github.com/angular/angular/issues/71050) (regression since [#69885](https://github.com/angular/angular/pull/69885)) | Since 22.2.0 the style scoping (`packages/compiler/src/shadow_css.ts`) also scopes nested rules, and gave `&.active` the `_ngcontent` attribute. Inside `:host`, `&` is the host element, which does not have that attribute. | `fix(compiler): do not scope `&`selectors nested in`:host`` | `packages/compiler/test/shadow_css/nesting_spec.ts`: four tests about `&` nested in `:host`, `:host()`, `:host-context()` and `:host .item` | `fix-demos/host-nesting.spec.ts`. Only components whose nested CSS reaches Angular's compiler are affected, such as JIT-compiled components: the Angular CLI flattens nested CSS before ahead-of-time compilation. |
